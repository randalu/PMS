## 2025-02-12 - Batched Query for lockForUpdate
**Learning:** Acquiring a lock for update inside a loop executes a separate DB query for every item, causing N+1 queries. Eager loading with `with('variant')` doesn't prevent this because `->variant()->lockForUpdate()` calls the query builder instead of the loaded relation.
**Action:** Pluck the IDs from the items collection and run a single batched query using `whereIn('id', $ids)->lockForUpdate()->get()->keyBy('id')` outside the loop, then look up the loaded models in the loop using `get()`. Also, `decrement()` updates the model in memory, so `refresh()` is often unnecessary and wastes a query.
