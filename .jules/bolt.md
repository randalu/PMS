## 2026-05-16 - Cache queries with defaults outside the cache closure
**Learning:** When using `Cache::rememberForever` for database queries that return null but use a fallback default, evaluate the default *outside* the cache closure. If evaluated inside, the default value is cached, meaning it becomes stale if the underlying code updates the default value for the application, and it misrepresents the actual state in the database.
**Action:** Always fetch the raw database value inside the cache closure. Apply the `?? $default` fallback on the return value of `Cache::rememberForever`.
## 2024-03-24 - Avoiding N+1 on HasMany Parent Inverse
**Learning:** When fetching children via a HasMany relationship (`$parent->children()->get()`), accessing the parent from the child model (`$child->parent`) triggers an N+1 query because Laravel doesn't automatically attach the parent model instance to the retrieved children, even though it already has it in memory.
**Action:** Use `$children->each->setRelation('parentRelationName', $parent)` immediately after retrieval to inject the loaded parent model into all children, preventing the N+1 query entirely without requiring an extra database call via `with('parent')`.
